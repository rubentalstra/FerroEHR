OPT-1.4 → ADL2 conversion fidelity (issue #188) navigation, all under `docs/specs/openehr/AM/docs/`:

- **Tuples (DV_ORDINAL/DV_QUANTITY/DV_SCALE)** — ADL2 syntax + `[units,magnitude]` matrix + ordinal `[value,symbol]∈{[{0},{[at1]}],...}`: `ADL2/master04.4-cadl_second_order.adoc §Tuple Constraints` (L64-321; deprecation of C_DV_QUANTITY/C_DV_ORDINAL at L148-152, L273-288). AOM2 model semantics: `AOM2/master04.3-constraint_model-second_order.adoc §Tuple Constraints` (concrete tuple member limited to C_PRIMITIVE_OBJECT). Class field tables: `UML/classes/org.openehr.am.aom2.c_attribute_tuple.adoc` (tuples: List<C_PRIMITIVE_TUPLE>, members: List<C_ATTRIBUTE>), `...c_primitive_tuple.adoc` (members: List<C_PRIMITIVE_OBJECT>), `...c_complex_object.adoc` (attribute_tuples: List<C_ATTRIBUTE_TUPLE>). AOM1.4 domain types are the GENERIC EXAMPLE names C_ORDINAL/ORDINAL/C_QUANTITY/C_QUANTITY_ITEM/C_CODED_TEXT in `AOM1.4/masterAppA-domain_extension.adoc` (UML `...aom14.c_ordinal/ordinal/c_quantity/c_quantity_item/c_coded_text`). SPEC-SILENCE: names C_DV_ORDINAL/C_DV_QUANTITY/C_DV_STATE/DV_SCALE and a `precision` field on C_QUANTITY_ITEM are NOT in vendored AM (oAP profile not vendored); C_QUANTITY_ITEM has only magnitude:Interval<Real> + units:String; ORDINAL has symbol:CODE_PHRASE + value:Integer.

- **Slots** — AOM2 `UML/classes/org.openehr.am.aom2.archetype_slot.adoc` (includes/excludes: List<ASSERTION> from LANG beom; is_closed:Boolean default False; expression form `EXPR_ARCHETYPE_REF matches EXPR_ARCHETYPE_ID_CONSTRAINT`). Validity VDFAI/VDSIV/VDSEV(+VDSSID/VDSSM/VDSSP/VDSSC) in `AOM2/master04.5-...class_definitions.adoc §Validity Rules: ARCHETYPE_SLOT` (L431-471). ADL2 text syntax `allow_archetype TYPE[id] occurrences∈{} ∈ { include archetype_id/value ∈ {/regex/} }`: `ADL2/master04.4 §Slots and Grouping` (L477-609). AOM1.4 slot: `UML/...aom14.archetype_slot.adoc` (includes/excludes: List<ASSERTION>), assertion tree = `...aom14.assertion.adoc` (expression:EXPR_ITEM, string_expression:String) + `...expr_binary_operator.adoc` (left/right_operand) + `...expr_leaf.adoc` (reference_type "constant"/"attribute"/"function"/"constraint"; item:Any). AOM1.4 assertion package = `AOM1.4/master05-assertion_package.adoc`.

- **Term bindings / value sets** — `AOM2/master07-terminology_package.adoc §Overview + §Class Descriptions §Validity Rules` (VTVSID/VTVSMD/VTVSUQ/VTSD/VTLC/VTTBK/VTCBK at L61-80). Class fields: `UML/...aom2.archetype_terminology.adoc` (term_bindings: Hash<terminology_id, Hash<code|path, Uri>> — keys are at/id-codes, ac-codes, OR paths; value_sets: Hash<ac-code, VALUE_SET>), `...aom2.value_set.adoc` (inherits TERMINOLOGY_RELATION → id:String + members:List<String>). ac-code→URI binding IS the AOM1.4 referenceSetUri equivalent. ADL2 ODIN shapes: `ADL2/master07.13-adl_terminology.adoc` (value_sets L60-65, term_bindings L66-72 + L294-370; keys L297-313; targets are unquoted URIs L315).

- **default_value** — `UML/...aom2.c_defined_object.adoc` (default_value:Any, 0..1, "set in a template, present in operational template; generally limited to leaf/near-leaf"; Inv_valid_default_value: valid_value(default_value)). C_ORDERED/C_DATE/C_TIME/C_DATE_TIME/C_DURATION/C_TERMINOLOGY_CODE each redefine default_value to their concrete type. ADL2 text: `ADL2/master06-default_values.adoc` — pseudo-attr `_default = (TYPE) <odin>` OR `_default = (json) <# ... #>`; IS serialisable in ADL text. So a converted default_value IS legal in an ADL2 source archetype.

- **Temporal pattern+range** — `ADL2/master04.5-cadl_primitive_types.adoc §Constraints on Dates,Times,Durations` (L356-508): pattern table L386-410 (yyyy-mm-??, hh:mm:XX, etc.), assumed value `pattern; assumed` L430, intervals `|2004-05-20..2004-06-02|` L432-450, Duration mixed `PWD/|P0W..P50W|` L487-508 (grammar `duration_constraint: duration_pattern '/' duration_interval`). AOM2: `UML/...aom2.c_temporal.adoc` (pattern_constraint:String) + C_ORDERED constraint:List<Interval<T>> (both coexist); C_DATE/C_TIME/C_DATE_TIME/C_DURATION carry both constraint:List<Interval<Iso8601_*>> + inherited pattern_constraint + validity-kind functions. AOM1.4 equivalent: `AOM1.4/master06-primitive_package.adoc` (c_date/c_time/c_date_time/c_duration — pattern OR Interval).

- **1.4 CONSTRAINT_REF / constraint_bindings** — `UML/...aom14.constraint_ref.adoc` (reference:String = ac-code; Inv Consistency: not any_allowed) + `UML/...aom14.archetype_ontology.adoc` (constraint_codes = the ac-codes = CONSTRAINT_REF.reference values; constraint_binding(terminology,code) fn). Conversion target = AOM2 C_TERMINOLOGY_CODE with constraint=ac-code (`UML/...aom2.c_terminology_code.adoc`) + VALUE_SET in value_sets + ac-code→URI in term_bindings.

- **ADL1.4→ADL2 conversion guidance** — `ADL2/master01-preface.adoc` (L84-126: backward-compat; at-coded ADL2.4 fully back-compatible with ADL1.4 RM data; conversion implemented in ADL Workbench, ADL1.4 paths generatable from ADL2) + `AOM2/master01-preface.adoc` L70-71 (populate new RESOURCE_DESCRIPTION.title with ADL1.4 template id) + `ADL2/master07.13` L485-499 (term_definitions+constraint_definitions merge into term_definitions; term_bindings+constraint_bindings merge into term_bindings) + `ADL2/master07.04` L39 (at→id code conversion). NO normative step-by-step conversion annex/algorithm and NO conversion REST endpoint exist in vendored text (see [[adl14-aom14-validity-location]]).
