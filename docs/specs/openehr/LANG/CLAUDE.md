# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this repository is

This is the **openEHR LANG (Generic Languages) specification component**. It contains no executable code — it is a set of normative specification documents written in **AsciiDoc**, plus computable model artifacts (UML, BMM). The published output is HTML on `specifications.openehr.org`.

It holds five specifications (see `manifest.json`, the authoritative descriptor):

| id | Title | Status |
|----|-------|--------|
| `odin` | Object Data Instance Notation (ODIN) — JSON-like notation used in ADL and BMM files | STABLE |
| `bmm` | Basic Meta-Model — compact human/machine-readable object-model definition format (XMI alternative) | STABLE |
| `bmm_persistence` | P_BMM — serialization format for BMM | STABLE |
| `BEL` | Basic Expression Language — model + syntax for archetype-rule expressions | STABLE |
| `EL` | Expression Language — advanced object/functional expression syntax built on BMM | DEVELOPMENT |

## Document structure (the big picture)

Each spec lives in `docs/<spec>/` and follows the openEHR multi-file convention:

- `master.adoc` — the assembly file. It includes boilerplate from a **sibling `specifications-AA_GLOBAL` repo** via the `{ref_dir}` attribute, then `include::`s the chapter files in order.
- `manifest_vars.adoc` — per-spec attributes: `:spec_title:`, `:spec_status:`, `:keywords:`, `:description:`.
- `master00-amendment_record.adoc` — the change log (see format below). **Every substantive change must add an entry here.**
- `masterNN-*.adoc` — numbered chapter files (the actual normative content). `masterAppX-*.adoc` are appendices.

`docs/index.adoc` is the component landing page; `docs/UML/class_index.adoc` is a generated index of all model classes, organised by UML package (`beom`, `bmm`, `bmm3`, `bmm_persistence`) under model `org.openehr.lang`.

`docs/*.html` files (e.g. `bmm.html`, `odin.html`) and `docs/UML/classes/` are **generated artifacts** — they are committed but never hand-edited. They are regenerated by the publishing toolchain. Recent commits like "Regenerate with latest Asciidoctor" reflect bulk regeneration; do not mix hand edits into them.

`computable/` holds the source-of-truth model files: `computable/UML/openEHR_UML-LANG.mdzip` (MagicDraw UML / XMI) and the BMM schemas `computable/BMM/openehr_lang_1.1.0.bmm.json` (BMM v2) and `computable/BMM/openehr_lang_1.1.0-bmm3.bmm.json` (BMM v3).

## Editing conventions

- **Edit the `masterNN-*.adoc` source, never the `.html`.** HTML is output.
- AsciiDoc attribute references like `{ref_dir}`, `{lang_release}`, `{spec_tickets}`, `{openehr_logo}` are resolved at build time from the publisher boilerplate (`global_vars.adoc`, `manifest_vars.adoc`). Do not inline literal values for them.
- `.asciidoctorconfig` sets `:component: LANG` and is used by IDE AsciiDoc live-preview plugins.

### Amendment record format

`master00-amendment_record.adoc` is a 4-column table (`Issue | Details | Raiser | Completed`). The newest entry carries the `[[latest_issue]]` and `[[latest_issue_date]]` anchors. Release boundaries are rendered as full-width header rows (`4+^h|*LANG Release 1.0.0*`). Change entries cite Jira issues using `{spec_tickets}/SPECLANG-NN[SPECLANG-NN^]`.

### Jira / change process

Changes are tracked in Jira project **SPECLANG** (roadmap key in `manifest.json`). Commit messages follow `Changes for SPECLANG-NN - <summary>` (see git history). When making a normative change: edit the chapter, add an amendment-record entry referencing the SPECLANG ticket, and bump the `latest_issue` version.

## Skills for this repo

When working here, prefer the dedicated openEHR spec-authoring skills over ad-hoc edits:
- `spec-authoring` — create/edit spec documents and manifest.json.
- `spec-amendment-record` — author amendment-record entries and release boundaries (matches the exact format above).
- `spec-review` — pre-release quality/convention review.
- `spec-governance` — releases, change requests, status promotion.

## Building

There is no build script in this repo. Rendering depends on the external **openEHR `specifications-AA_GLOBAL`** toolchain (Asciidoctor-based), which supplies the boilerplate that `{ref_dir}` resolves to and defines attributes such as `lang_release`. To render a single spec locally with Asciidoctor, the `ref_dir` and release attributes must be supplied, e.g. `asciidoctor -a ref_dir=<path-to-specifications-AA_GLOBAL> -a lang_release=latest docs/odin/master.adoc`. Do not commit locally-generated HTML unless intentionally regenerating published output.
