## Spec-file corrections / notes

- **No ADMIN OpenAPI exists in the vendored ITS-REST 1.0.3 tree.** `specifications/` contains only `overview`, `ehr`, `query`, `definition` `.openapi.yaml`; there are no admin operations under `operations/` (only `schemas/ehr/AdminEntry.yaml` / `UMAdminEntry.yaml`, which belong to the EHR API, not an admin service). Per `docs/VERSIONS.md` the ADMIN API is dev-branch only. Admin requirements are therefore out of scope for this chapter — no requirements extracted for admin.
- **TRIAGE §D (OPT-upload Accept/406 leniency):** classified below as `its-rest-query-definition-admin-R30` (adl1.4) and `R38` (adl2). The upload operations declare **no `Accept` parameter and no `406` response**, and their success bodies are produced as `application/xml` (adl1.4) / `text/plain` (adl2) only. The OAS neither mandates nor forbids honoring a client `Accept` on upload; our server's current 2xx-on-`Accept: application/json` is a leniency, not a spec violation, but it emits a non-declared content type — flagged medium.
