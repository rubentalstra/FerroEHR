## File-existence notes / corrections

- **`master07-grammar.adoc` contains no grammar text.** It is an AsciiDoc shell
  that `include::`s `grammar/AqlParser.g4` and `grammar/AqlLexer.g4`. A
  filesystem search (`find … -name '*.g4'`) confirms **no `.g4` files are
  vendored** under `docs/specs/openehr/QUERY/`. The ANTLR4 grammar itself is
  therefore not part of the vendored oracle; grammar-level requirements below
  are derived from the prose of `master03-syntax.adoc`, not from the grammar
  file.
- **`LATEST_VERSION` / `ALL_VERSIONS` are NOT defined anywhere in the vendored
  AQL chapter** (`master02`–`master07`). The task brief and blueprint row 11
  reference these, but they are not normative constructs of the vendored AQL
  1.1 syntax spec — they belong to the openEHR SM Platform Query Service /
  versioning surface, not this chapter. No requirement is raised for them here;
  flagged so the parent audit does not treat their absence in AQL as a defect.
- The result-structure spec (`master04`) explicitly declares annotated
  RESULT_SETs (openEHR `Result set`) to be **out of scope of AQL** — "not
  formally defined by this specification, and are considered an artefact of the
  relevant API or service definition." Only the raw `Array<Array<Any>>` shape
  is normative here (see R48–R49).

## Requirements

| ID | Requirement | Citation | Category | Risk |
|----|-------------|----------|----------|------|
| query-aql-R1 | AQL keywords are **not** case-sensitive: `SELECT`, `Select`, `select`, `SeLeCt` are all processed identically. Reserved keywords are `SELECT AS FROM CONTAINS WHERE ORDER BY LIMIT OFFSET DISTINCT` + operators `AND OR NOT LIKE matches exists < > = !` + the listed functions + literals `true false NULL`. A tokenizer must fold keyword case and recognise the full reserved set. | master03-syntax.adoc §"Reserved words and characters" (L17–24) | behaviour | medium |
| query-aql-R2 | An AQL statement **must at least contain the `SELECT` and `FROM` clauses**; both are mandatory. A query missing either must be rejected as invalid. | master03-syntax.adoc §"Query structure / Overview" (L910–918) | rejection-duty | high |
| query-aql-R3 | Clauses **must occur in this order**: `SELECT` (mandatory), `FROM` (mandatory), `WHERE` (optional), `ORDER BY` (optional), `LIMIT` (optional). A query whose clauses are out of this order must be rejected. | master03-syntax.adoc §"Query structure / Overview" (L910–918) | rejection-duty | high |
| query-aql-R4 | A **variable name must be unique within an AQL statement**. Two class expressions declaring the same variable must be rejected. | master03-syntax.adoc §"Variables / Syntax" (L92) | rejection-duty | high |
| query-aql-R5 | A variable name is an initial letter followed by any number of alphanumerics and underscores, **and must not clash with an AQL reserved word**; variable names are not case-sensitive. A reserved word used as a variable name must be rejected. | master03-syntax.adoc §"Variables / Syntax" (L95) | validity-fn | high |
| query-aql-R6 | A parameter is `$` followed by a name of letters, digits and underscores; it **cannot contain spaces and cannot be an AQL reserved word**. Malformed parameter names must be rejected. | master03-syntax.adoc §"Parameters / Syntax" (L106) | validity-fn | medium |
| query-aql-R7 | When a `WHERE`-criterion parameter is substituted, a value that is **not a number or boolean must be substituted with quotes added** (string/date/time/datetime quoted; numbers and booleans unquoted) — the substituted value follows the same literal-quoting rules as a directly-written literal. | master03-syntax.adoc §"Parameters / Syntax" NOTE (L113) | behaviour | medium |
| query-aql-R8 | The **standard predicate** has exactly a left-hand operand (openEHR path), an operator, and a right-hand operand (criterion value, parameter, or another openEHR path). The operator is one of `> >= = < <= !=`. | master03-syntax.adoc §"Predicates / Standard predicate" (L149–157) | mandatory-attr | medium |
| query-aql-R9 | An **archetype predicate** (e.g. `[openEHR-EHR-COMPOSITION.encounter.v1]`) is a shortcut with no left operand/operator, carrying only an archetype id, and **is only used within an AQL `FROM` clause**. An archetype predicate appearing outside `FROM` must be rejected. | master03-syntax.adoc §"Predicates / Archetype predicate" (L161) | rejection-duty | high |
| query-aql-R10 | The archetype predicate `[<archetype-id>]` is semantically equivalent to the standard predicate `archetype_node_id = '<archetype-id>'`; implementations may canonicalise it to that form. A node-only predicate `[at0002]` is equivalent to `[archetype_node_id=at0002]`. | master03-syntax.adoc §"Predicates / Archetype predicate" (L169–181) + §"Node predicate" (L187–197) | behaviour | medium |
| query-aql-R11 | Node predicate `[at0002, 'name value']` (or `[at0002, $param]`) is the shortcut form of `[archetype_node_id=at0002 and name/value='name value']`. The comma form maps the second operand to `name/value`. | master03-syntax.adoc §"Predicates / Node predicate" (L213–225) | behaviour | medium |
| query-aql-R12 | Node predicate with a **term-code name shortcut** `[at0002, snomed_ct(3.1)::313267000]` (form `terminology_id::code_string\|value\|`) maps to `archetype_node_id=at0002 and name/defining_code/code_string='313267000' and name/defining_code/terminology_id/value='snomed_ct(3.1)'`; a bare at-code as the name operand (e.g. `[at0002, at0003]`) uses **terminology_id `'local'`**. | master03-syntax.adoc §"Predicates / Node predicate" (L227–241) | behaviour | medium |
| query-aql-R13 | An **identified path** is a variable reference optionally followed by a predicate and/or an openEHR path. Its three legal forms are: `var/path`, `var[predicate]`, and `var[predicate]/path`. (An identified path may appear in any clause **except `FROM`**.) | master03-syntax.adoc §"Identified Paths / Syntax" (L253, L268–286) | mandatory-attr | medium |
| query-aql-R14 | The comparison operators are exactly `= > >= < <= != LIKE matches`. `!=` means not-equal. These are the only comparison operators permitted in identified expressions. | master03-syntax.adoc §"Operators / Comparison operators" table (L296–308) | mandatory-attr | medium |
| query-aql-R15 | `LIKE` matches a string (or a value with a string representation) against a pattern where `?` matches exactly one character and `*` matches zero-or-more characters. **`LIKE` always matches the entire string value** — a substring intent requires the pattern to start and end with `*`. | master03-syntax.adoc §"Operators / LIKE" (L310–330) | behaviour | medium |
| query-aql-R16 | In a `LIKE` pattern, a literal `?` or `*` **must be escaped with a backslash** (`\?`, `\*`); an unescaped `?`/`*` is the wildcard. If the pattern contains no wildcards, `LIKE` behaves exactly like `=`. | master03-syntax.adoc §"Operators / LIKE" (L328–332) | behaviour | medium |
| query-aql-R17 | The `matches` right-hand operand is enclosed in `{}` and may be (a) a cADL-style comma-separated value list, (b) a URI, or (c) a `TERMINOLOGY()` function call. A `matches` RHS not in one of these forms must be rejected. | master03-syntax.adoc §"Operators / matches" (L334–416) | rejection-duty | medium |
| query-aql-R18 | In a `matches` value list, items may be of type **string, date/time, integer, or real**, and **quotes are required for strings and date/times** (numbers unquoted). The relationship among list items is **OR** (match one item of the list). | master03-syntax.adoc §"Operators / matches" cADL list constraint (L338–365) | behaviour | medium |
| query-aql-R19 | A `matches` URI operand is an IETF RFC 3986 URI enclosed in `{}`, and **URIs are not case-sensitive**. A terminology URI decomposes into scheme (terminology), authority (terminology service), path (function name), and query args. | master03-syntax.adoc §"Operators / matches" URI (L369–402) | behaviour | low |
| query-aql-R20 | `AND` is a binary boolean conjunction: `true` iff both operands are `true`. `OR` is a binary boolean disjunction: `true` iff any operand is `true`. These evaluate to boolean results. | master03-syntax.adoc §"Logical operators / AND, OR" (L420–426) | behaviour | low |
| query-aql-R21 | `NOT` is a **unary** operator negating a boolean operand, returning a boolean. In `WHERE` it forms an identified expression; `NOT (A AND B)` is equivalent to `NOT A OR NOT B` (De Morgan) per the worked example — negation semantics must be correct, not merely syntactic. | master03-syntax.adoc §"Logical operators / NOT" (L428–458) | behaviour | medium |
| query-aql-R22 | `EXISTS` is a **unary** operator whose operand is an identified path, returning boolean (`true` iff data at the path exists). **`EXISTS` can be used only in the `WHERE` clause.** `EXISTS` outside `WHERE` must be rejected. | master03-syntax.adoc §"Logical operators / EXISTS" (L473–475) | rejection-duty | medium |
| query-aql-R23 | `NOT CONTAINS` in the `FROM` clause expresses an **exclusion constraint** — the absence of any containment relationship between a parent and potential child. It must be executed as negated containment, not silently ignored. | master03-syntax.adoc §"Logical operators / NOT" (L460–471) + §"Containment" (L981–987) | behaviour | high |
| query-aql-R24 | Containment uses `CONTAINS` between two class expressions (left = parent of right). Multiple containment constraints combine with **`AND`, `OR`, and parentheses `()`** — i.e. **OR-CONTAINS is normative** and must be supported (e.g. `CONTAINS (OBSERVATION o1 OR OBSERVATION o2)`). Rejecting a spec-legal OR/AND containment is a conformance defect. | master03-syntax.adoc §"Containment" (L960–979) | behaviour | high |
| query-aql-R25 | A **class expression** has part one (mandatory: RM class name) plus at least one of part two (variable name) or part three (a standard or archetype predicate). A class expression with only a class name and neither a variable nor a predicate must be rejected. | master03-syntax.adoc §"Class expressions" (L792–796) | rejection-duty | high |
| query-aql-R26 | All classes referenced in the `FROM` clause **must be defined by the Reference Model** (e.g. `EHR`, `COMPOSITION`, `OBSERVATION`, `EVALUATION`). A `FROM` class name not defined by the RM must be rejected. | master03-syntax.adoc §"FROM" (L926–928) | rejection-duty | high |
| query-aql-R27 | Aggregate functions (`COUNT MIN MAX SUM AVG`) compute a single result over the set of input values selected by the identified-path expression, and **unless specified otherwise they ignore `NULL` input values**. | master03-syntax.adoc §"Functions / Aggregate functions" (L505–520) | behaviour | medium |
| query-aql-R28 | `COUNT` syntax is `COUNT([DISTINCT] expression\|*)`; `COUNT(*)` counts all result rows **including duplicates and `NULL` values**; `DISTINCT` counts only distinct values; return type is always **Integer**; with no matching rows it returns **`0`**. | master03-syntax.adoc §"Functions / COUNT" (L533–541) | behaviour | medium |
| query-aql-R29 | `MIN`/`MAX` return **`NULL`** when there are no matching rows; input value type must be **String, Date, Time, Integer or Real**, and that input type **determines the return type**. A non-comparable/other input type is out of the accepted set. | master03-syntax.adoc §"Functions / MIN, MAX" (L543–555) | validity-fn | medium |
| query-aql-R30 | `SUM`/`AVG` return **`NULL`** when there are no matching rows; input value type must be **Integer or Real** (return type derived from input). Applying `SUM`/`AVG` to a non-numeric input is outside the accepted type set and must be rejected/typed-errored, not silently coerced. | master03-syntax.adoc §"Functions / SUM, AVG" (L557–569) | rejection-duty | high |
| query-aql-R31 | `LENGTH(expression)` — arg String, result **Integer**. Wrong-typed argument is outside the declared signature. | master03-syntax.adoc §"Functions / String functions / LENGTH" (L589–592) | mandatory-attr | low |
| query-aql-R32 | `CONTAINS(expression, substring)` (string function) — both args String, result **Boolean**; `true` iff `expression` contains `substring`. (Distinct from the `CONTAINS` containment operator; disambiguated by clause/context.) | master03-syntax.adoc §"Functions / String functions / CONTAINS" (L594–597) | mandatory-attr | medium |
| query-aql-R33 | `POSITION(substring, expression)` returns the 1-based index of the first occurrence of `substring` in `expression`, or **`0` if not present**; **the first character is position `1`**; result Integer. Off-by-one (0-based) is a defect. | master03-syntax.adoc §"Functions / String functions / POSITION" (L599–603) | behaviour | medium |
| query-aql-R34 | `SUBSTRING(expression, position, length)` extracts starting at the `position`-th character (**first char = position `1`**); `length` is **optional** and when omitted extracts to end-of-string; result String. | master03-syntax.adoc §"Functions / String functions / SUBSTRING" (L605–611) | behaviour | medium |
| query-aql-R35 | `CONCAT(expr1, expr2, …)` concatenates **one or more** String args; `CONCAT_WS(separator, expr1, …)` concatenates String args inserting `separator` between them. | master03-syntax.adoc §"Functions / String functions / CONCAT, CONCAT_WS" (L613–619) | mandatory-attr | low |
| query-aql-R36 | Numeric functions: `ABS(expr)` (Real/Integer, result type derived); `MOD(x, y)` = remainder of x/y (Real/Integer); `CEIL(expr)`/`FLOOR(expr)` return an **Integer** (nearest ≥ / ≤ respectively); `ROUND(expression, decimal)` where `decimal` is Integer **defaulting to `0`** when omitted, result type derived from `expression`. | master03-syntax.adoc §"Functions / Numeric functions" (L621–662) | behaviour | medium |
| query-aql-R37 | `CURRENT_DATE()` returns a String formatted **`YYYY-MM-DD`**; `CURRENT_TIME()` → **`hh:mm:ss`**; `CURRENT_DATE_TIME()`/`NOW()` → **`YYYY-MM-DDThh:mm:ss.sss±hh:mm`**; `CURRENT_TIMEZONE()` → **`±hh:mm`**. All accept **no arguments** (`NOW` is an alias of `CURRENT_DATE_TIME`). Passing arguments to any of these is invalid. | master03-syntax.adoc §"Functions / Date and time functions" (L664–695) | behaviour | medium |
| query-aql-R38 | `TERMINOLOGY(operation, service_api, params_uri)` takes **exactly three String arguments**; return type is `Any` (depends on `operation`/`service_api`). Wrong arity or non-String args must be rejected. | master03-syntax.adoc §"Functions / TERMINOLOGY" (L699–706) | validity-fn | medium |
| query-aql-R39 | `TERMINOLOGY()` may be used in `WHERE` in three ways: (a) as the direct RHS of `matches`; (b) **embedded inside `{}` of a `matches` RHS, in which case the interpreter must merge the explicit codes with the function results during semantic analysis** to generate a valid code list; (c) as a boolean value expression tested against `= true`. | master03-syntax.adoc §"Functions / TERMINOLOGY" (L748–767) | behaviour | high |
| query-aql-R40 | Integer literals: no thousands separators (commas/periods) are allowed and **hexadecimal is not supported**. Real literals require a decimal point (e.g. `3.14`, `-1.0`). A hex or grouped-digit numeric literal must be rejected. | master03-syntax.adoc §"Built-in Types / Integer data, Real data" (L865–871) | rejection-duty | medium |
| query-aql-R41 | Boolean literals are the **case-insensitive** `true`/`false`. String literals are enclosed in single or double quotes and **must not contain line breaks**. `NULL` is a keyword indicating missing/unknown. | master03-syntax.adoc §"Built-in Types / Boolean data, String data" (L873–879) + §"Literals" (L861) | behaviour | low |
| query-aql-R42 | Date/time literals are quoted strings complying with **ISO 8601**; the AQL processor **infers the underlying date/time type from context and from the ISO 8601 form** — ISO 8601 **extended** format is identified as a date/datetime value, whereas **basic** format (e.g. `19860101`, `12:00:00+09:30`) is identified as a **string** value. This typing distinction affects comparison semantics. | master03-syntax.adoc §"Built-in Types / Dates and Times" (L881–904) | behaviour | medium |
| query-aql-R43 | An `ORDER BY` sorting expression is an identified path optionally followed by one of `DESC`/`DESCENDING`/`ASC`/`ASCENDING`; when the sort type is omitted, **`ASC` (ascending) is assumed by default**. | master03-syntax.adoc §"ORDER BY / Syntax" (L1102–1111) | behaviour | medium |
| query-aql-R44 | Sorting requires the data identified by the path to be **comparable** — it relies on equal/less-than/greater-than as available to primitives and **`Ordered` types** (i.e. ordered-magnitude comparison for `DV_ORDERED`, not string comparison). Multiple sorting expressions are comma-separated and applied left-to-right as tie-breakers. | master03-syntax.adoc §"ORDER BY / Syntax" (L1109, L1113) | behaviour | high |
| query-aql-R45 | With no `ORDER BY`, result ordering is **undefined** by this specification (may be implementation-defined or random). Conformance must not assume a default order. | master03-syntax.adoc §"ORDER BY" NOTE (L1096–1098) | behaviour | low |
| query-aql-R46 | `LIMIT row_count [OFFSET offset]`: `row_count` and `offset` are integers, **`row_count` minimum value is `1`**, **`offset` minimum value is `0`**, `offset` defaults to `0` when omitted; the offset of the first row is `0` (not 1). A `LIMIT 0` or negative offset must be rejected. | master03-syntax.adoc §"LIMIT / Syntax" (L1133–1142) | validity-fn | medium |
| query-aql-R47 | It is **not allowed to use `LIMIT` together with `TOP` in the same query** (and vice versa); `TOP` is deprecated. A query using both must be rejected. | master03-syntax.adoc §"SELECT / TOP" (L1075) + §"LIMIT" (L1125) | rejection-duty | medium |
| query-aql-R48 | `DISTINCT` removes duplicate rows (a row is a duplicate iff every column value matches another row); when `DISTINCT` is used, `LIMIT`/`OFFSET` apply to the rows **remaining after** duplicates are filtered out. | master03-syntax.adoc §"SELECT / DISTINCT" (L1057–1059) + §"LIMIT" (L1127) | behaviour | medium |
| query-aql-R49 | A `SELECT` column expression is an identified path, a function, a literal value, or a plain variable name defined in `FROM`; a bare variable name retrieves the **full object** of that variable's type. Each column expression may carry a `name alias` via `AS <name>`, where the alias conforms to the AQL variable naming rule. | master03-syntax.adoc §"SELECT / Syntax" (L1014–1022) + §"Name alias" (L1090–1092) | mandatory-attr | low |
| query-aql-R50 | The raw AQL result structure is a 2-dimensional table of type **`Array<Array<Any>>`**, where a missing/unknown data item is the **`NULL`** value. Result serialization must represent missing leaves as NULL rather than omitting/erroring. | master04-result_structure.adoc (L3) | serialization | medium |
