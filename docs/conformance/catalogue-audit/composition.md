## Defects

- **D1 — has_composition realization unregistered (3 cases + binding).** Catalogue: `has_composition` realized as `GET /ehr/{ehr_id}/composition/{version_uid}` with TRUE→`ok(200)`, FALSE→`not_found(404)`; no `ambiguities:` tag, no register entry. Spec: SM i_ehr_composition.adoc `has_composition(…): Boolean` ("Return True if a Composition version … exists"); master07 "The result must be TRUE"/"must be FALSE"; the vendored OAS has no composition-existence endpoint. The register's own AMB-23 handling says "200 is the positive return, 404 the negative (**the has_composition precedent**)" — the precedent entry does not exist, while the identical gaps got AMB-19 (has_query) and AMB-23 (has_contribution). Fix: add an AMB entry (SM Boolean existence op with no ITS-REST probe, realized via the resource GET), tag `has_composition`, `has_composition-bad_composition`, `has_composition-bad_ehr`, and cite it from the binding.
- **D2 — CNF↔SM name divergence `get_composition_version()` unregistered (2 cases).** Spec: master07 line 231 "Service Model reference: `I_EHR_COMPOSITION._get_composition_version()_`" vs SM i_ehr_composition.adoc, which defines only `get_composition_at_version`. Catalogue: `get_composition_version` / `get_composition_versions` resolve `sm_operation: …get_composition_at_version` correctly but justify it only by prose ("AMB-13 precedent; see REQUIREMENTS.md") — AMB-13's text covers exclusively the ADL14 `get_opts` divergence, and every other chapter's instance of this class got its own entry (AMB-14 EHR, AMB-16 validate_opt, AMB-35 demographic). Fix: add the composition-chapter entry, machine-tag both cases, drop the ghost file reference.
- **D3 — `create_composition-same_opt_twice`: missing AMB-21 tag + stale comment.** YAML comment: "the ITS-REST composition_create OAS assigns no status code to the persistent-uniqueness conflict, and **the frozen create_composition binding maps no `conflict` outcome** — see schedule/composition/REQUIREMENTS.md (binding extension + ambiguity candidate)". Reality: the register carries AMB-21 ("Bind conflict → 409 on create_composition") and the binding maps `conflict: {status: 409} # … bound per AMB-21`. Precedent: the directory analogue case machine-tags its AMB-25. Fix: `ambiguities: [AMB-5, AMB-21]`, rewrite the comment to cite AMB-21, drop the ghost reference.
- **D4 — `update_composition-non_existent`: self-contradictory header comment.** Comment claims "an unknown preceding version is a 404 (version_not_found)"; the case expects `not_found` and the binding maps `version_not_found → 412` (overview §If-Match: false condition ⇒ MUST 412 on an existing target; unknown PATH target ⇒ 404 per the overview's RFC 9110 conditional-evaluation pointer). The machine-readable parts are mutually consistent; the prose misnames the kind and the code. Fix: rewrite the header to the path-uid/404 derivation already given inline on the expect line.
- **D5 — `update_composition-wrong_template` corpus ground is a placeholder.** master07 flow 3 requires a **valid** COMPOSITION of the *other* provisioned OPT; the fixture is the minimal_event payload with `template_id` relabeled `cnf.vitals` (root archetype `openEHR-EHR-OBSERVATION.minimal.v1` — not in the cnf.vitals OPT), so it is invalid against its named template while MANIFEST declares `verdict: valid` ("structural placeholder pending corpus authoring"). With template_mismatch and validation_failed sharing 422, kind-by-fixture classification is unsound on this ground. Fix: author a genuinely cnf.vitals-conformant event COMPOSITION for `minimal_event.wrong_template.json`; align the manifest entry (and add its missing `template_id` field).
- **D6 — `create_composition-event_bad_opt`: comment names the wrong absent OPT.** Comment: "the composition's referenced OPT (cnf.minimal_event) is absent"; fixture/manifest: the reference is `cnf.absent_template.v99`; `cnf.minimal_event` is not any artifact's id. Fix: correct the comment.
- **D7 — `get_versioned_composition` under-asserts the official flow cell.** Official: "return a valid VERSIONED_COMPOSITION object, referencing the VERSION it contains". Case: `instance_of` only — not even `uid == ${versioned_object_uid}`. The OAS resource carries `uid` (assertable now) and the `…/versioned_composition/{uid}/version` subresource exists for the version-reference half. Fix: assert the uid equality (and preferably probe the /version subresource), or register the representation limit with citation.
- **D8 — `delete_composition-non_existent`: unregistered correction of the official Description cell.** Official B.8.c Description reads "Delete persistent COMPOSITION" (upstream copy-paste defect); catalogue writes "Delete non-existent COMPOSITION" with no editorial register entry (AMB-12/27/28/45 precedent: upstream editorial defects are registered). Fix: editorial ambiguity entry noting the corrected cell.
