### D1 — SF-FLAT-commit_roundtrip_ctx_defaults: step-3 equivalence unsatisfiable as encoded (+ phantom section citation)
- YAML says: step 3 `{ assert: equivalent, to: committed, ignoring: [ctx_defaults, server_assigned] }` after committing `cnf.flat.vitals.minimal_ctx`; spec_refs cite "ITS-REST simplified_formats master06 §ctx defaults".
- Spec says: master06 (`docs/specs/openehr/ITS-REST/docs/simplified_formats/master06-context_information.adoc`, opening sentence): "To simplify the input, the flat formate offers the option to set context values which set default values in the rm-tree" — ctx/ keys are INPUT defaults that materialise into RM attributes; master05 §EVENT_CONTEXT shows the same data on OUTPUT as `context/_participation:i|…` / `context/_health_care_facility|…` RM paths. The registered ignore-set (`vocab/selectors.yaml` ctx_defaults) covers only `context/start_time`, `context/setting`, `composer` — not the participation/health_care_facility/id_namespace ctx keys the fixture carries. master06 has no heading "ctx defaults" (real headings: §Composer, §Language and Territory, §time, §setting, …).
- Proposed fix: per the case's own TODO — either restrict step 3 to clinical-leaf comparison (steps 2/4 already do this) or extend the evaluator/ignore-set to normalise ctx-input keys to their master05 RM-path forms, with the master06 input-default citation; repoint the spec_ref to "master06 §time + §setting".

### D2 — SF-MAP-context: two wrong citations
