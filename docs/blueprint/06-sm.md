## Normative requirements (what a compliant CDR MUST do)

### A. Global conventions (all services)

1. **Native-API architecture / formal equivalence.** The platform exposes a
   nominal *native API* reached through protocol adapters (REST, SOAP,
   protobuf, Kafka, …). An implementation may realise one spec call as several
   of its own **iff** the pre/post-conditions match and the group is
   transactionally protected — otherwise it "is introducing unspecified
   semantics". (`openehr_platform/master02-overview.adoc` §General
   Assumptions, §Interface Calls.)
2. **Transactionality + CQS.** Every interface call is either a query (no
   state change) or a command; "any single call constitutes a self-standing
   transaction" leaving the service consistent; `create_*` returning the new
   id is the sanctioned exception. (`master02-overview.adoc` §Interface Calls,
   §Global Conventions/Functional Style.)
3. **Error model.** Failures interrogated via `I_STATUS.last_call_failed():
   Boolean` + `last_call_status(): CALL_STATUS`
   (`code: CALL_STATUS_TYPE`, `call_name`, `call_string`, `meaning`,
   `message`); the statuses cover auth errors, precondition violations, and
   server exceptions; mapping to a stateless response-envelope style is
   explicitly permitted. Services extend `CALL_STATUS_TYPE` by inheritance
   (base values: `success`, `auth_failure`, `precondition_violation`,
   `object_version_does_not_exist`, `versioned_object_does_not_exist`,
   `exception`, `ehr_id_does_not_exist`, `party_id_does_not_exist`,
   `file_not_writable`, `version_mismatch`).
   (`master02-overview.adoc` §Functional Style;
   `master03-common_package.adoc` `I_STATUS`/`CALL_STATUS`/`CALL_STATUS_TYPE`.)
4. **Auth out of band.** Authentication/authorisation is "assumed to have been
   dealt with before any particular call" (OAuth, RFC 7235 + RBAC); no auth
   arguments on any call (removed in 0.9.2). (`master02-overview.adoc`
   §Functional Style; `master00-amendment_record.adoc`.)
5. **List handling.** Every unbounded-list call takes `item_offset: Integer`
   (0-based) + `items_to_fetch: Integer` (0 ⇒ all).
   (`master02-overview.adoc` §List Handling.)
6. **Naming conventions.** `ehr_id` = `EHR.ehr_id.value`;
   `versioned_object_uid` = `VERSIONED_OBJECT.uid.value`; `version_uid` =
   `VERSION.uid.value` (`uuid::system::n`); `preceding_version_uid`;
   `object_id`; `time` ISO 8601. (`master02-overview.adoc` §Global Naming
   Conventions.)

### B. Version-update semantics (the commit envelope)

7. **Server-side CONTRIBUTION on every versioned write.** Calls that
   create/update a versioned top-level object "implicitly require the creation
   of a new `CONTRIBUTION` on the server side, as well as one or more new
   `ORIGINAL_VERSION` objects, and in creation cases, new `VERSIONED_OBJECTS`."
   (`master03-common_package.adoc` §Version Update Semantics.)
8. **`UPDATE_VERSION<T>` client payload.** `preceding_version_uid:
   OBJECT_VERSION_ID [0..1]` (mandatory except first version),
   `lifecycle_state: Terminology_code [1]` (always mandatory; e.g.
   `532|complete|`, `553|incomplete|`, `523|deleted|`), `attestations:
   List<ATTESTATION> [0..1]`, `data: T [1]`, `audit: UPDATE_AUDIT [1]`.
   Concrete bindings: `UV_COMPOSITION`, `UV_FOLDER`, `UV_PARTY`,
   `UV_PARTY_RELATIONSHIP`. (`master03-common_package.adoc`
   §Version Update Semantics; `UML/classes/update_version.adoc`,
   `uv_composition.adoc`, `uv_folder.adoc`.)
9. **`UPDATE_AUDIT` server completion.** Client supplies `change_type`
   (invariant `Change_type_valid`: code in the openEHR *audit change type*
   group), `description?`, `committer: PARTY_PROXY`; the **server** generates
   `time_committed` and `system_id`. (`UML/classes/update_audit.adoc`.)
10. **`I_VALIDITY_CHECKER` gate.** `definitions_valid(a_content: LOCATABLE)`
    (archetype/template ids known locally) and `content_valid(a_content)`
    (valid RM instance) are the named preconditions of every content-writing
    call. (`master03-common_package.adoc` `I_VALIDITY_CHECKER`.)

### C. Definitions service

11. **`I_DEFINITION_ADL14`** — 16 calls: `has/valid/upload/get/list/
    list_matching/delete_archetype`, `has/valid/upload/get/list/
    list_matching/delete_opt`, `archetypes_count`, `opts_count`; upload =
    replace-if-exists, must be valid; regex (`id_pattern`) listing; errors
    `invalid_archetype`, `invalid_template`, `artefact_does_not_exist`,
    `invalid_id_pattern`. (`master04-definition_package.adoc`;
    `UML/classes/i_definition_adl14.adoc`.)
12. **`I_DEFINITION_ADL2`** — the `AUTHORED_ARCHETYPE` artefact family keyed
    by `ARCHETYPE_HRID`: `has/valid/upload/get/delete_artefact`,
    `list_artefacts/archetypes/templates/opts`, `list_matching_artefacts`,
    four `*_count` calls. (`UML/classes/i_definition_adl2.adoc`.)
13. **`I_DEFINITION_QUERY`** — `has_query`, `valid_query(text, a_type)`,
    `store_query(text, a_type, name?): QUERY_DESCRIPTOR`, `store_query_set`
    (spec-incomplete, see §4), `list_queries`, `list_matching_queries`
    (PERL regexes over query id + referenced artefact ids), `delete_query`,
    `queries_count`. Qualified names `<namespace>::<query-name>`; missing
    namespace ⇒ `"misc"`; formalism (`a_type`) case-insensitive with optional
    `::`-separated version, no version ⇒ major `"1"`.
    (`master04-definition_package.adoc` conventions;
    `UML/classes/i_definition_query.adoc`, `query_descriptor.adoc`.)

### D. EHR service

14. **`I_EHR_SERVICE`** — `has_ehr`, `has_ehr_for_subject`, `create_ehr`
    (pre: supplied EHR_STATUS has no subject; absent status ⇒ default:
    `is_modifiable`/`is_queryable` True, `subject` = `PARTY_SELF`),
    `create_ehr_with_id` (pre `not has_ehr`; error
    `ehr_create_fail_duplicate_id`), `create_ehr_for_subject(_with_id)`
    (error `ehr_for_subject_already_exists`), `get_ehr: EHR_SUMMARY`,
    `get_ehrs_for_subject`, `i_ehr`. (`openehr_platform/
    master05-ehr_service.adoc`; `UML/classes/i_ehr_service.adoc`.)
15. **`I_EHR`** — per-EHR accessor with four mandatory interface attributes:
    `ehr_status`, `directory`, `compositions`, `contributions`.
    (`UML/classes/i_ehr.adoc`.)
16. **`I_EHR_STATUS`** — "with implicit Contribution creation": versioned
    get/at-time/at-version/versioned-object reads; `set/clear_ehr_queryable`,
    `set/clear_ehr_modifiable` (each a versioned flag mutation);
    `update_other_details`. (`UML/classes/i_ehr_status.adoc`.)
17. **`I_EHR_DIRECTORY`** — `has_directory`, `has_path` (path =
    slash-separated Folder `name`s), create/get/at-time/at-version/versioned,
    `update_directory` (**preceding version must be supplied and correct** —
    optimistic lock), `delete_directory` = logical delete (new version,
    contents removed). (`UML/classes/i_ehr_directory.adoc`.)
18. **`I_EHR_COMPOSITION`** — `has_composition`, `get_composition_latest/
    at_time/at_version`, `get_versioned_composition`, `create_composition` /
    `update_composition` (pre `has_ehr` + `definitions_valid` +
    `valid_content`; server creates VERSIONED_OBJECT + ORIGINAL_VERSION +
    CONTRIBUTION), `delete_composition` = logical delete: new version, content
    removed, lifecycle `523|deleted|`. (`UML/classes/i_ehr_composition.adoc`.)
19. **`I_EHR_CONTRIBUTION`** — `has/get_contribution`;
    `commit_contribution(an_ehr_id, versions: List<UPDATE_VERSION>, an_audit:
    UPDATE_AUDIT): UUID` — the explicit **atomic multi-version commit**;
    `list_contributions(ehr_id, time_range?, item_offset, items_to_fetch)`;
    `contribution_count(ehr_id, time_range?)`.
    (`UML/classes/i_ehr_contribution.adoc`.)
20. **`EHR_SUMMARY`** — `ehr_id`, `system_id`, `ehr_status`, `time_created`,
    **`contribution_count: Integer [1]`, `composition_count: Integer [1]`**.
    (`UML/classes/ehr_summary.adoc`.)

### E. Demographic service

21. **`I_DEMOGRAPHIC_SERVICE`** — `create_party(a_version: UV_PARTY): UUID`
    (pre `definitions_valid` + `valid_content`),
    `create_party_relationship(UV_PARTY_RELATIONSHIP): UUID`, `i_party`,
    `i_party_relationship`; creates VERSIONED_OBJECT + ORIGINAL_VERSION +
    CONTRIBUTION server-side. (`openehr_platform/
    master06-demographic_service.adoc`.)
22. **`I_PARTY`** — `has_party`, `has_party_version_id`, `get_party`
    (+at_time/at_version), `update_party`, `delete_party` (post
    `not has_party`). (`UML/classes/i_party.adoc`.)
23. **`I_PARTY_RELATIONSHIP`** — the same family for `PARTY_RELATIONSHIP`
    (has/get/at-time/at-version/update/delete).
    (`UML/classes/i_party_relationship.adoc`.)

### F. EHR Index service

24. **`I_EHR_INDEX`** — an **N:M** subject↔EHR association store ("in a
    privacy-supporting environment, this enables EHRs to be persisted with
    only an EHR id"); both multi-subject-per-EHR ("dangerous error condition,
    needs to be detected and rectified") and multi-EHR-per-subject
    (duplicate-EHR) are conditions to *manage*, not reject. Five calls:
    `add_ehr_subject(ehr_id, subject_id: OBJECT_REF, status?:
    RESOURCE_STATUS, loc_desc?: LOCATION_DESC)`,
    `update_ehr_subject_status`, `update_ehr_subject_loc_desc`,
    `remove_ehr_subject`, `remove_subject`. `RESOURCE_STATUS.instance_type ∈
    {Primary, Duplicate, Supplementary}`. (`openehr_platform/
    master07-ehr_index_service.adoc`; `UML/classes/i_ehr_index.adoc`,
    `resource_status.adoc`.)

### G. Query service

25. **`I_QUERY_SERVICE`** — `execute_stored_query(exec_spec:
    STORED_QUERY_EXECUTE_SPEC, row_offset?, rows_to_fetch?, ehr_ids?):
    RESULT_SET` and `execute_ad_hoc_query(ADHOC_QUERY_EXECUTE_SPEC, …)`;
    `row_offset ≤ 0` ⇒ 0, `rows_to_fetch ≤ 0` ⇒ all. Stored-query id =
    `reverse-domain '::' semantic-id ['/' version]`; absent version ⇒ latest.
    (`openehr_platform/master08-query_service.adoc`;
    `UML/classes/i_query_service.adoc`.)
26. **The `is_queryable` population gate.** Empty `ehr_ids` ⇒ the query runs
    over **all EHRs whose `EHR_STATUS.is_queryable = True`** — normative.
    (`master08-query_service.adoc`.)
27. **`ADHOC_QUERY_EXECUTE_SPEC.formalism`** defaults to `"aql"`;
    `query_parameters: Hash<String,String> [1]` tag-matched to open query
    parameters. (`UML/classes/adhoc_query_execute_spec.adoc`,
    `stored_query_execute_spec.adoc`.)
28. **`RESULT_SET`** — `columns: List<RESULT_SET_COLUMN> [1]` (`name`,
    `archetype_id?`, `path?`), `id [1]`, `creation_time [1]`,
    `query: RESULT_QUERY_DESCRIPTOR [0..1]` (adds `executed` — the
    parameter-substituted text), `rows [0..1]` positionally aligned to
    columns. (`UML/classes/result_set.adoc`, `result_set_column.adoc`,
    `result_query_descriptor.adoc`.)

### H. Terminology service

29. **`I_TERMINOLOGY_SERVICE`** — nine calls: `get_terminology_ids`,
    `has_terminology`, `get_terminology_description`, `has_term`, `get_term`,
    `subsumes(terminology_id, ref_code, candidate_child_code)` (strict
    subsumption), `value_set_validate`, `has_value_set`, `get_value_set`;
    optional `at_date` gives temporal terminology semantics.
    (`openehr_platform/master12-terminology_service.adoc`;
    `UML/classes/i_terminology_service.adoc`.)
30. **Extract classes** — `Terminology_description`, `Terminology_extract`
    (flat value set / ref-set / subsumption hierarchy), `Term_code`,
    `Defined_term`, `Term_relationship`, `Terminology_relation` with the
    invariant `local_code /= Void xor external_code /= Void`.
    (`UML/classes/terminology_extract.adoc`, `terminology_relation.adoc`.)

### I. Message service

31. **`I_EHR_EXTRACT_SERVICE`** — `export_ehrs(ehr_id): List<EXTRACT>`,
    `export_ehr_extracts(extract_spec: EXTRACT_SPEC): List<EXTRACT>`,
    `import_ehr(ehr_id?: UUID, extract)` (optional fixed EHR id),
    `import_ehr_extract(ehr_id, extract)` — all availability `0..1`, no
    pre/post/errors defined. (`openehr_platform/master09-message_service.adoc`;
    `UML/classes/i_ehr_extract_service.adoc`.)
32. **`I_TDD_SERVICE`** — `import_tdd(an_ehr_id: UUID, tdd: String)`;
    `import_tdds` (bulk — unsigned in source). (`UML/classes/
    i_tdd_service.adoc`.)

### J. System Log service

33. **IHE ATNA-compliant system log** — the *only* normative statement is the
    overview table ("System Log | IHE ATNA-compliant system log.",
    `master02-overview.adoc` line 38); `i_system_log.adoc` is an empty stub.
    The contract is sourced from IHE ATNA itself.

### K. Subject Proxy service

34. **`I_SUBJECT_PROXY_SERVICE` + `I_DATA_BINDING`** — symbolic subject
    variables over heterogeneous back-ends; register subject / add variable /
    register data set / register binding / add binding frame / get_variable /
    get_data_set / reset; the `SUBJECT_PROXY`/`SUBJECT_VARIABLE`/
    `SUBJECT_DATA_SET`/`SAMPLE<T>`→`OPENEHR_SAMPLE`(`result: RESULT_SET`)/
    `VARIABLE_VALUE` model; `I_DATA_BINDING.get_frame(subject_id, frame_id):
    DATA_FRAME_SAMPLE` with per-environment `ENV_BINDING`/`DATA_FRAME`
    (`model_type` e.g. `"openehr"`, `"hl7-fhir"`). Consumers: Task Plans /
    Decision Logic. (`openehr_platform/master10-subject_proxy_service.adoc`;
    `UML/classes/i_subject_proxy_service.adoc`, `i_data_binding.adoc`.)

### L. Admin service

35. **`I_ADMIN_SERVICE`** — per-service statistics: `list_contributions
    (a_service: PLATFORM_SERVICE, time_interval?)`, `contribution_count`,
    `versioned_composition_count`, `composition_version_count`; physical
    deletes: `physical_ehr_delete` (pre `has_ehr`) and
    `physical_party_delete` (also deletes related party relationships; error
    `party_id_does_not_exist`). (`openehr_platform/master15-admin_service.adoc`;
    `UML/classes/i_admin_service.adoc`.)
36. **`I_ADMIN_ARCHIVE`** — `archive_ehrs(ehr_ids?)` /
    `archive_parties(party_ids?)`: "move to archival storage".
    (`UML/classes/i_admin_archive.adoc`.)
37. **`I_ADMIN_DUMP_LOAD`** — `export_ehrs(file_sys_loc, logical_fmt?:
    EXPORT_FORMAT {openehr_canonical_xml, openehr_canonical_json},
    comp_fmt?: COMPRESSION_FORMAT {zip, 7z}, enc_format?: ENCODING_FORMAT)`;
    `load_ehrs(file_sys_loc)` — imports with duplicate EHR ids fail;
    `EXPORT_SPEC.segment_split_size: Integer [1]` (kb);
    `DUMP_LOAD_FAIL_REPORT` per entity; error `file_not_writable`.
    (`UML/classes/i_admin_dump_load.adoc`, `export_spec.adoc`.)

### M. SIM-B + SDF

38. **SIM-B (Simplified IM 'B')** — the `S_*` class model (S_COMPOSITION,
    S_ENTRY subtree, S_ITEM/S_ELEMENT, S_DV_* leaves), the `APP_CONTEXT`
    (`ctx/`) vocabulary, and the transformation-rule tables (`collapse()`,
    `copy()`, `default`, `skip`; e.g. `OBSERVATION.data/state` collapse,
    `DV_CODED_TEXT.defining_code.{code_string, terminology_id}` →
    `code`/`terminology`, `DV_TEXT.formatting/language/encoding` → skip —
    documented-lossy). No `S_*` class declares an invariant; the rules are
    the only formal constraints. (`simplified_im_b/master02/05/06/07-*.adoc`.)
39. **SDF (Serial Data Formats)** — normative leaf encodings: ISO 8601
    strings incl. partial forms; `Terminology_code` `"[id::code]"` /
    `Terminology_term` `"[id::code|text|]"`; ODIN interval strings
    (`|0 .. 5|`, `|>= 1939-02-01|`, `|5.0 ±0.5|`); `DV_ORDINAL`
    `"value|term"`, `DV_SCALE` `"real|term"`, `DV_QUANTITY` **`"value,unit"`
    (comma)**, `DV_PROPORTION` `"num/den;KIND"`; EhrScape `|`-prefixed-key
    object variants. Load-bearing absences: **no flat-path/key syntax, no
    MIME types**; `DV_PARSABLE`/`DV_INTERVAL<T>` = `CHECK`; the string parser
    = `TBD: define`. FLAT is not CNF/ECC-gated — SDF alignment is interop
    quality, not a conformance blocker.
    (`serial_data_formats/master03-data_values.adoc`, `master04-syntax.adoc`.)
