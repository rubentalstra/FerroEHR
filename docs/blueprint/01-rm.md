## Normative requirements (what a compliant CDR MUST do)

### A. Change control & versioning (`common/master06-change_control_package.adoc`)

1. **Version container model.** Every top-level structure (COMPOSITION, EHR_STATUS, FOLDER tree,
   PARTY) is versioned inside a `VERSIONED_OBJECT<T>` with a globally unique `uid` (HIER_OBJECT_ID)
   and an `owner_id` referencing the owning repository (e.g. the EHR). The internal representation is
   implementation-defined; only each version's form is normative.
   — `common/master06` §"Versioned Objects"; invariants `Version_count_valid`, `All_version_ids_valid`,
   `Latest_version_valid`, `Uid_validity` in `UML/classes/org.openehr.rm.common.versioned_object.adoc`.
2. **Indelibility.** A versioned repository is indelible: *all* logical changes (add, modify, correct,
   delete, import, attest) are physical commits of new `VERSION`s (or new `ATTESTATION`s on existing
   versions). Nothing is ever physically removed. — `common/master06` §"Contributions".
3. **Change-type coding.** `commit_audit.change_type` uses openEHR terminology group
   `audit change type`: new item = `249|creation|`; deletion = `523|deleted|`; correction =
   `250|amendment|`; content change = `251|modification|`; import = `249|creation|`; attestation =
   `666|attestation|`. — `common/master06` §"Contributions" (bullet list).
4. **Logical deletion procedure.** Delete = commit a new version whose `data` is Void, with
   `lifecycle_state` = `523|deleted|`, via the normal commit path; prior states remain reconstructable.
   — `common/master06` §"Logical Deletion".
5. **Contribution = atomic change-set.** Every commit creates a `CONTRIBUTION` listing the affected
   VERSIONs, with its own audit; "An attempt to commit a Contribution should only succeed if each
   Version and/or Attestation in the Contribution is committed successfully" (nested-transaction
   semantics). The Contribution list is the basis for record rollback/history.
   — `common/master06` §"Contributions", §"Committal and Audits".
6. **Audit copy rule.** The Contribution audit's `system_id`, `committer`, `time_committed` "should be
   copied into the corresponding attributes of the `commit_audit` of each `VERSION` included in the
   `CONTRIBUTION`". — `common/master06` §"Committal and Audits".
7. **Server-side commit time.** `time_committed` (Contribution and Version audits) reflects the time of
   committal to the EHR server ("computed on the server"), not client time.
   — `common/master06` §"Committal and Audits".
8. **Version identification.** `VERSION.uid` is an `OBJECT_VERSION_ID` =
   `object_id::creating_system_id::version_tree_id`, where `object_id` is a copy of the owning
   `VERSIONED_OBJECT.uid`. Trunk `version_tree_id`s start at 1 and increment by 1; branches use the
   two-extra-number form (`2.3.3`). The tuple {object_id, creating_system_id, version_tree_id} is
   globally unique. — `common/master06` §"Version Identification", §"Local Versioning",
   §"Distributed Versioning".
9. **VERSION invariants.** `Owner_id_valid`: `owner_id.value = uid.object_id.value`;
   `Preceding_version_uid_validity`: `uid.version_tree_id.is_first xor preceding_version_uid /= Void`;
   `Lifecycle_state_valid`: coded in terminology group `version lifecycle state`.
   — `UML/classes/org.openehr.rm.common.version.adoc`.
10. **ORIGINAL_VERSION invariants.** `Attestations_valid` (non-empty if present), `Is_merged_validity`
    (`other_input_version_ids = Void xor is_merged`), `Other_input_version_uids_valid` (non-empty if
    present). — `UML/classes/org.openehr.rm.common.original_version.adoc`.
11. **Version lifecycle state machine.** States: `532|complete|`, `553|incomplete|`, `523|deleted|`,
    `800|inactive|`, `801|abandoned|`; transitions per the RM state machine (abandon/retrieve/
    deactivate/reactivate/delete). "Any transition requires the commit of a *new version*, even if the
    content is otherwise unchanged." — `common/master06` §"Version Lifecycle",
    §"Abandoned and Inactive States" (transition table).
12. **Incomplete-state validation relaxation.** For an `incomplete` commit: "mandatory attributes may
    be absent … single-valued attributes may have null values and container attributes may be empty …
    All other validity requirements must be satisfied … data may be missing, but it may not be wrong"
    (existence/cardinality lower limits treated as zero). Complete-state commits of such data must be
    rejected as invalid. Transition `incomplete → complete` generates a new VERSION regardless.
    — `common/master06` §"Incomplete Content" (NOTE).
13. **IMPORTED_VERSION semantics.** A copied `ORIGINAL_VERSION` is committed locally wrapped in an
    `IMPORTED_VERSION` whose own contribution/commit_audit record the *local* act of committal; its
    `uid`/`preceding_version_uid` are functions delegating to the wrapped original (no distinct id).
    "The `ORIGINAL_VERSION` instance is never modified." Local time-travel queries use the local commit
    times. — `common/master06` §"Version and its Subtypes", §"Copying".
14. **Distributed rules.** Local modifications to copied versions must use *branch* version ids;
    `creating_system_id` is set to the local system for locally created versions; "no system should
    create a new Versioned object (with a new uid) without first determining that it does not already
    have one with the same uid"; branch versions cannot be copied without their preceding/trunk
    versions. — `common/master06` §"Distributed Versioning", §"Subsequent Local Modifications".
15. **Merging.** A merge creates a new trunk `ORIGINAL_VERSION` with `other_input_version_uids`
    recording every considered input version (even if its content was unused); disjoint merge (duplicate
    record repair) follows the prescribed per-container procedure ending with a `deleted` trunk version
    in the source container. — `common/master06` §"Version Merging", §"Disjoint Merging".
16. **Attestation.** `ATTESTATION` is an `AUDIT_DETAILS` subtype: may be the `commit_audit` itself
    (signing at committal, optionally `is_pending = True`) or added post-hoc to
    `ORIGINAL_VERSION.attestations`; empty `items` = attests the whole version, otherwise `items` are
    paths within the data; `reason` coded from group `attestation reason`; existing attestations are
    *not* assumed valid for subsequent versions. — `common/master06` §"Attestation";
    `common/master04-generic_package.adoc` §"Attestation"; invariants in
    `UML/classes/org.openehr.rm.common.attestation.adoc`.
17. **Digital signature.** Optional: serialize the Version object (signature Void) to a canonical text
    form, hash (integrity) and optionally sign (authenticity), radix-64 encode per openPGP (RFC 4880);
    the signature is stored with the version. — `common/master06` §"Digital Signature".

### B. Archetyped / generic packages (`common/master03`, `common/master04`)

18. **LOCATABLE invariants.** `Links_valid` (non-empty if present), `Archetyped_valid`
    (`is_archetype_root xor archetype_details = Void`), `Archetype_node_id_valid` (non-empty).
    `ARCHETYPED.Rm_version_valid` (non-empty). — `UML/classes/org.openehr.rm.common.locatable.adoc`,
    `…common.archetyped.adoc`.
19. **Top-level uid convention.** For top-level types (COMPOSITION, EHR_STATUS, top FOLDER, PARTY) it
    is "recommended to set the `uid` value to a copy of the `uid.object_id()` value of the owning
    `VERSION` object". — `common/master03` §"Unique Node Identification";
    `UML/classes/org.openehr.rm.ehr.ehr_status.adoc` (NOTE), `…common.folder.adoc` (NOTE).
20. **Pathability.** `PATHABLE` provides `item_at_path()`/`items_at_path()`/`path_exists()`/
    `path_unique()` over the compositional hierarchy; all intra-EHR references are path-based
    (`LOCATABLE_REF` = OBJECT_VERSION_ID + path, or `DV_EHR_URI`). — `common/master03` §"The PATHABLE
    Class", §"Unique Node Identification".
21. **Feeder audit.** `FEEDER_AUDIT` is attachable to any LOCATABLE granularity; a new Composition
    version must be created "for each received version, even where the content does not change at all";
    synthesized nodes are marked with a FEEDER_AUDIT with change type "synthesised"; feeder audit is
    content (retained across versions), not commit audit. — `common/master03` §"Feeder System Audit"
    (Version Detection, Structural Correspondence).
22. **Party proxies & participations.** Record subject is always `PARTY_SELF` (three `external_ref`
    usage schemes all supported); `PARTY_IDENTIFIED.Basic_validity`:
    `name /= Void or identifiers /= Void or external_ref /= Void`; `PARTICIPATION.Function_valid` /
    `Mode_valid` and `AUDIT_DETAILS.System_id_valid` / `Change_type_valid` are terminology-bound.
    — `common/master04` §"Referring to Demographic Entities"; invariants in
    `UML/classes/org.openehr.rm.common.{party_identified,participation,audit_details}.adoc`.
23. **Revision history.** `REVISION_HISTORY`/`REVISION_HISTORY_ITEM` provide the interoperable
    audit-per-revision view of a VERSIONED_OBJECT (each item = version id + all audits incl.
    attestations). — `common/master04` §"Revision History".

### C. Directory & tags (`common/master05`, `common/master07`)

24. **Folders are versioned trees of references.** `VERSIONED_FOLDER = VERSIONED_OBJECT<FOLDER>`:
    "each of its versions is a Folder structure rather than a single Folder"; `FOLDER.items` are
    `OBJECT_REF`s — "Folder structures do not contain Compositions, only references to them"; multiple
    folders may reference the same target. Folders may be added/removed at any time relative to the
    referenced Compositions. — `common/master05` §Overview; `ehr/master04-ehr_package.adoc` §"Folders".
25. **Directory paths.** Folder paths are built from `name` values with bracketed uniqueness modifiers.
    — `common/master05` §"Paths".
26. **Tags.** `ITEM_TAG`: `Inv_key_valid` (`not key.is_empty and key.is_justified`), `Inv_value_valid`
    (non-empty if present); tags live in one logical `EHR.tags` list, may be added at any time, are not
    part of the annotated content and "do not cause re-versioning of the content"; one distinct instance
    per use; tag keys/values must be queryable via AQL and service search.
    — `common/master07`; `ehr/master04` §"Tags"; `UML/classes/org.openehr.rm.common.item_tag.adoc`.

### D. EHR package (`ehr/master04-ehr_package.adoc`)

27. **EHR creation.** Creating an EHR yields the root EHR object + an EHR_STATUS + an EHR_ACCESS,
    normally "created and committed in a Contribution, just as any Composition would be"; the creation
    operation must accept `system_id`, `ehr_id`, optional `subject_id` (PARTY_SELF allows fully
    anonymous EHRs), `is_queryable`, `is_modifiable`. "It is strongly recommended that a UUID always be
    used for the `ehr_id`." — §"EHR Creation".
28. **EHR immutables.** `system_id`, `ehr_id`, `time_created` are "immutable after creation".
    — §"Root EHR Object".
29. **EHR invariants.** `Contributions_valid`, `Ehr_access_valid`, `Ehr_status_valid`,
    `Compositions_valid`, `Directory_valid`, `Folders_valid`, and `Directory_in_folders`:
    `folders /= Void implies folders.item(1) = directory` (directory is the first `folders` member, kept
    for pre-1.1.0 compatibility). — `UML/classes/org.openehr.rm.ehr.ehr.adoc`; `ehr/master04` §"Folders".
30. **EHR_STATUS semantics.** Mandatory `subject: PARTY_SELF` (1..1), `is_queryable` (1..1),
    `is_modifiable` (1..1), optional archetyped `other_details`; `Is_archetype_root` invariant. The
    EHR_STATUS object "is always modifiable"; `is_modifiable = False` forbids writes to *EHR contents*
    (Compositions, Folders — everything except EHR_STATUS); an inactive EHR "will remain queryable,
    unless the `is_queryable` attribute is also set to `False`" (population-query inclusion flag).
    — `UML/classes/org.openehr.rm.ehr.ehr_status.adoc`; `ehr/master04` §"EHR Status",
    §"EHR Active Status".
31. **EHR cloning.** An EHR created as a logical clone reuses the source `ehr_id`; `system_id` is that
    of the receiving system. — §"EHR Identifier Allocation"; cross-ref `common/master06` §"Copying".
32. **Composition category.** `COMPOSITION.category` coded from terminology group
    `composition category` (`event`, `episodic`, `persistent`); persistent Compositions are maintained
    as a single logical instance updated by new versions; episodic ones may be closed out via lifecycle
    `inactive`/`abandoned` on the owning version. — §"Compositions", §"Episodic Compositions";
    invariant `Category_validity` in `UML/classes/org.openehr.rm.composition.composition.adoc`.
33. **COMPOSITION invariants.** `Category_validity`, `Territory_valid` (ISO countries code-set),
    `Language_valid` (languages code-set), `Content_valid` (non-empty if present), `Is_archetype_root`.
    — `UML/classes/org.openehr.rm.composition.composition.adoc`.
34. **VERSIONED_COMPOSITION invariants.** All versions share the first version's `archetype_node_id`
    (`Archetype_node_id_valid`) and constant persistence category (`Persistent_validity`).
    — `UML/classes/org.openehr.rm.ehr.versioned_composition.adoc`.
35. **Versioning scenarios.** Case 0 (new local authoring → new VERSIONED_COMPOSITION +
    ORIGINAL_VERSION), Case 1 (local correction → change_type "correction"/amendment), Case 2 (feeder
    import → IMPORTED_VERSION + ORIGINAL_VERSION pair, feeder audit in `COMPOSITION.feeder_audit`),
    Case 3 (content selected from a received Extract → new locally authored ORIGINAL_VERSION).
    — §"Versioning Scenarios".
36. **Historical views.** A previous state of the record = the previous *informational* state at that
    node (what users could see then), using local commit times — required for medico-legal
    reconstruction. — §"Historical Views of the Record"; `common/master06` §"Copying" (last para).
37. **EHR_ACCESS.** One versioned EHR_ACCESS per EHR carrying `scheme` (non-empty, `Scheme_valid`) and
    scheme-defined settings; all changes versioned. — `ehr/master04` §"EHR Access";
    `UML/classes/org.openehr.rm.ehr.ehr_access.adoc`.

### E. Composition content & Entry (`ehr/master05`–`master08`)

38. **EVENT_CONTEXT invariants.** `Setting_valid` (terminology group `setting`),
    `Participations_validity`, `location_valid` (non-empty if present).
    — `UML/classes/org.openehr.rm.composition.event_context.adoc`.
39. **ENTRY invariants.** `Language_valid` (languages code-set), `Encoding_valid` (character-sets
    code-set), `Subject_validity` (`subject_is_self implies subject.generating_type = "PARTY_SELF"`),
    `Other_participations_valid`, `Is_archetype_root` (every ENTRY is an archetype root). SECTION:
    `Items_valid`. — `UML/classes/org.openehr.rm.composition.{entry,section}.adoc`.
40. **Instruction/Action model.** INSTRUCTION `Activities_valid` (non-empty if present); ACTIVITY
    `Action_archetype_id_valid` (non-empty); INSTRUCTION_DETAILS `Activity_path_valid`; ISM_TRANSITION
    `Current_state_valid` (group `instruction states`) and `Transition_valid` (group `instruction
    transitions`). The standard ISM defines states INITIAL/PLANNED/POSTPONED/SCHEDULED/CANCELLED/
    ACTIVE/SUSPENDED/ABORTED/COMPLETED/EXPIRED (CANCELLED, ABORTED, COMPLETED terminal; EXPIRED
    pseudo-terminal); "The current state of an Activity is thus found not in the `ACTIVITY` instance
    but in the most recent `ACTION` instance for that Activity" — i.e. instruction state must be
    derivable by query. — `ehr/master08` §"The Standard Instruction State Machine (ISM)",
    §"Model Overview"; class invariant files as cited.
41. **Observation timing semantics.** `HISTORY.origin` / `EVENT.time` always mean the time of sampling
    (not of laboratory measurement). — `ehr/master08` §"Clinical Semantics of Event Time".

### F. Data structures (`data_structures/master04`–`master06`)

42. **ELEMENT null semantics.** `is_null() = (value = Void)`; `is_null() xor null_flavour = Void`;
    `null_flavour` coded from group `null flavours`; `null_reason /= Void implies is_null()`.
    — `UML/classes/org.openehr.rm.data_structures.element.adoc`.
43. **HISTORY/EVENT invariants.** `Events_valid` (`events` non-empty or `summary` present);
    `Periodic_validity` (`is_periodic xor period = Void`); `Period_consistency` (all event offsets
    multiples of period); `EVENT.Offset_validity1` (`offset = time.diff(parent.origin)`);
    `INTERVAL_EVENT.Math_function_validity` (group `event math function`) and
    `Interval_start_time_valid` (`interval_start_time = time - width`).
    — `UML/classes/org.openehr.rm.data_structures.{history,event,interval_event}.adoc`.
44. **Structure constraints.** `ITEM_LIST.items` and every `ITEM_TABLE` row's items are ELEMENT-only.
    — `UML/classes/org.openehr.rm.data_structures.{item_list,item_table}.adoc`.

### G. Data types (`data_types/master04`–`master10`; class files)

45. **Text.** `DV_TEXT.Valid_value` (non-empty), `Language_valid`/`Encoding_valid` (code-sets),
    `Mappings_valid`/`Formatting_valid` (non-empty if present); `TERM_MAPPING.Purpose_valid`
    (group `term mapping purpose`) and `Match_valid` (`is_valid_match_code`: one of `<`,`>`,`=`,`?`).
    — `UML/classes/org.openehr.rm.data_types.{dv_text,term_mapping}.adoc`.
46. **Quantities.** `DV_PROPORTION`: `Type_validity`, `Precision_validity` (`precision = 0 implies
    is_integral`), `Is_integral_validity`, `Fraction_validity`, `Unitary_validity` (`denominator = 1`),
    `Percent_validity` (`denominator = 100`), `Valid_denominator` (`/= 0.0`).
    `DV_INTERVAL.Limits_consistent` (strictly comparable and `lower <= upper` when bounded).
    `DV_DURATION.Value_valid` (`valid_iso8601_duration`).
    — `UML/classes/org.openehr.rm.data_types.{dv_proportion,dv_interval,dv_duration}.adoc`.
47. **Encapsulated.** `DV_MULTIMEDIA`: `Not_empty` (`is_inline or is_external`), `Media_type_valid`
    (media-types code-set), `Compression_algorithm_validity`, `Integrity_check_validity`
    (check implies algorithm), `Integrity_check_algorithm_validity`, `Size_valid` (`>= 0`).
    `DV_PARSABLE`: `Formalism_valid`, `Size_valid`.
    — `UML/classes/org.openehr.rm.data_types.{dv_multimedia,dv_parsable}.adoc`.

### H. Demographic (`demographic/master02-demographic_package.adoc`)

48. **Demographic separation & versioning.** Demographic (PARTY/ROLE/ACTOR…) data live in their own
    repository, versioned via the same change-control machinery as EHR content; PARTY invariants
    include `Identities_valid` (non-empty) and `Uid_mandatory` (`uid /= Void`).
    — `demographic/master02`; `UML/classes/org.openehr.rm.demographic.party.adoc`.

### I. Integration (`integration/master02-integration_package.adoc`)

49. **GENERIC_ENTRY.** A CONTENT_ITEM sibling of SECTION/ENTRY with a single archetypable `data`
    attribute; valid value of `COMPOSITION.content`; "instances can only be committed to the record as
    part of a `COMPOSITION` instance. `GENERIC_ENTRY` data are thus audit-trailed and versioned in the
    normal way"; usable inside SECTION hierarchies; carries FEEDER_AUDIT meta-data.
    — `integration/master02` §"Semantics of GENERIC_ENTRY".

### J. EHR Extract (`ehr_extract/master05`, `master09`)

50. **X_VERSIONED_OBJECT.** Extract items are top-level objects expressed as `X_VERSIONED_OBJECT<T>`
    subtypes (X_VERSIONED_COMPOSITION/…EHR_STATUS/…EHR_ACCESS/…FOLDER/…PARTY), which "turns most
    functional properties of `VERSIONED_OBJECT` into data attributes"; `versions` holds wrapped copies
    of ORIGINAL_VERSIONs; `revision_history` optionally included (alone via
    `EXTRACT_VERSION_SPEC.includes_data = False`). — `ehr_extract/master05` §"Design".
51. **Whole-composition versioning in extracts.** Historical versions are sent as *whole* Compositions
    ("include all Compositions in their whole form"), never as cumulative diffs; receivers needing
    version analytics must have local version control. — `ehr_extract/master09` §"Versioning Semantics".
52. **Extract creation algorithm.** Given the primary Composition set, optional folder structure,
    `include_multimedia`, and `follow_links` depth: create the EHR_EXTRACT with folder structure;
    write PARTYs into a demographics chapter; per Composition create an `X_VERSIONED_COMPOSITION` with
    `is_primary` set; resolve each `OBJECT_REF` target into the appropriate chapter and rewrite refs so
    `namespace = "local"`; include/exclude DV_MULTIMEDIA content per flag; follow DV_LINKs recursively
    (targets `is_primary = False`). — `ehr_extract/master09` §"Creation Semantics".
53. **Extract import.** First receipt for a subject creates a clone EHR reusing the source EHR id;
    first receipt of an item creates a `VERSIONED_OBJECT` with the received `uid.object_id()`; each
    received ORIGINAL_VERSION is committed wrapped in an IMPORTED_VERSION as part of a Contribution.
    — `common/master06` §"Copying" (referenced from the Extract IM); `ehr/master04` §"EHR Identifier
    Allocation".

### K. Support (`support/master02`–`master07`)

54. **Assumed/support types.** The support package defines the assumed foundation types, the
    terminology-service and measurement-service interfaces the invariants above dispatch through
    (`terminology(...)`, `code_set(...)` — e.g. groups `composition category`, `setting`,
    `instruction states`, code-sets `countries`, `languages`, `media types`), and the definition
    package constants; identification is delegated to BASE (`support/master04` is a pointer).
    — `support/master03-assumed_types.adoc`, `support/master05-terminology_package.adoc`,
    `support/master07-definition_package.adoc`.
