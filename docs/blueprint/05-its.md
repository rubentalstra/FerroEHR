## Normative requirements (what a compliant CDR MUST do)

### A. General protocol (Overview spec)

1. **HTTP method subset.** Implement resource semantics with GET, HEAD, POST, PUT, DELETE, OPTIONS as tabulated. — `docs/overview/Requests_and_responses.md` §HTTP Methods.
2. **AuthN/AuthZ.** Services SHOULD implement an HTTP authentication framework (scheme unspecified); if present, services MUST use `WWW-Authenticate`/`Proxy-Authenticate` and return `403`/`401`/`407` whenever applicable. — §Authentication and authorization.
3. **Direct commit = native versioning.** For change-controlled resources (COMPOSITION, EHR_STATUS, FOLDER, …) services MUST allow direct `PUT`/`POST`/`DELETE`, and these MUST internally be executed the "native" way (CONTRIBUTION wrapping a VERSION). — §openEHR-VERSION and openEHR-AUDIT_DETAILS.
4. **Committal-metadata headers.** Services MUST accept the custom request headers `openEHR-VERSION.*` and `openEHR-AUDIT_DETAILS.*` (e.g. `lifecycle_state: code_string="532"`, `change_type`, `description`, `committer`); none are mandatory, but "whatever is provided it MUST be merged with the default VERSION and VERSION.audit_details attributes on commit runtime". Code tables for lifecycle_state (532/553/523) and change_type (249/250/251/252/523/666/253) are given. — same section.
5. **If-Match / optimistic locking.** If a received `If-Match` condition evaluates false the service MUST NOT perform the method and MUST respond `412 Precondition Failed`, SHOULD also return the latest `version_uid` in `Location` and `ETag`. Format: a `version_uid` in double quotes; the header is declared `required: true` on the versioned write operations that reference it. — §If-Match and accidental overwrites; `parameters/header/If-Match.yaml`.
6. **openEHR-TEMPLATE_ID.** MUST be used when committing a COMPOSITION via a simplified data format that cannot carry `archetype_details.template_id`. — §openEHR-TEMPLATE_ID.
7. **Location.** Services MUST return `Location` whenever a create or update was performed (MAY on others); identifiers in the URL SHOULD follow the resource-identification semantics. `openEHR-uri` response header MAY be sent (DV_EHR_URI form). — §Location and openEHR-uri.
8. **Prefer negotiation.** `Prefer: return=minimal` (default when absent) → minimal/no body, `Location` MUST be present, `204 No Content` SHOULD be used when there is no payload; `Prefer: return=representation` → full representation SHOULD be in the payload, `Location` MAY. Services with the capability SHOULD accept and honor `Prefer: resolve_refs` (return resources instead of OBJECT_REF lists). — §Representation details negotiation; `parameters/header/Prefer.yaml` (enum `return=representation|return=minimal`, default minimal).
9. **ETag / Last-Modified.** `ETag` is an opaque state token; recommended value = the unique id of the resource (double-quoted `version_uid` on VERSION resources, per `headers/ETag*.yaml`). `Last-Modified` "should be taken from VERSION.commit_audit.time_committed.value". Both SHOULD be present in all responses targeting VERSION, VERSIONED_OBJECT or similarly identified resources. — §ETag and Last-Modified; `headers/ETag.yaml`, `headers/ETag_VERSION.yaml`.
10. **Status-code vocabulary.** The tabulated subset (200, 201, 204, 400, 401, 403, 404, 405, 406, 408, 409, 412, 415, 422, 500, 501) MUST be used as described; other codes MAY be used only if not conflicting/overlapping. `400` = generic client error when no other 4xx fits. — §HTTP status codes.
11. **Error detail bodies.** On errors 400–500 services MAY return more details if `Prefer: return=representation` is present (example body: `message` + `code` + `errors[]` of DV_CODED_TEXT — non-normative example). — §HTTP status codes.
12. **Resource identification.** `version_uid` lexical form `object_id::creating_system_id::version_tree_id`; `uid_based_id` = either a `version_uid` (OBJECT_VERSION_ID) or a `versioned_object_uid` (HIER_OBJECT_ID), the latter resolving to the latest version; COMPOSITION.uid SHOULD be populated from the enclosing VERSION uid (RM 1.0.4+ recommendation). — `docs/overview/Resources.md` §Resource identification; `docs/overview/Glossary_and_conventions.md`.
13. **At least one canonical format.** Services MUST support at least one of the openEHR **XML** or **JSON** formats; alternative (SDT) formats MAY be supported. — `docs/overview/Resources.md` §Data representation.
14. **XML rules.** XML request payloads and results MUST be valid against the published XSDs (ITS-XML). Unsupported XML request payload → `415`; unfulfillable `Accept: application/xml` → `406`; `Content-Type: application/xml` MUST be present on responses except `204`. — §XML Format.
15. **JSON rules.** SHOULD be valid against the published ITS-JSON schemas. Attribute names MUST be lowercase snake_case per the RM; metadata attributes prefixed `_`; `_type` used whenever polymorphism is involved or the static type is abstract, its value MUST be the uppercase RM class name; null/empty-list attributes SHOULD be absent; attribute order not mandatory. Unsupported JSON payload → `415`; unfulfillable `Accept: application/json` → `406`; `Content-Type: application/json` MUST be present except on `204`. — §JSON Format.
16. **SDT media types.** When alternative formats are used, clients and servers MUST use `application/openehr.wt.flat+json` (simSDT/FLAT), `application/openehr.wt.structured+json` (structSDT), `text/plain` (ADL2 templates / AQL), `application/openehr.nc.flat+json` (ncSDT), `application/openehr.tds2+xml` (TDS); same 415/406/Content-Type discipline. — §Alternative data formats.
17. **Datetime format.** Query parameters and path segments that are dates/times MUST always use *extended* ISO 8601 (`YYYY-MM-DDThh:mm:ss.sss[Z|±hh:mm]`). Body date/time values are preserved as sent and SHOULD be returned in the original format ("avoiding any format change"). — §Datetime format.

### B. EHR API (`ehr.openapi.yaml`, server URL `https://{baseUrl}/v1`)

Per-operation response sets from `operations/*.yaml` (each `$ref`ing `responses/*.yaml`, which fix the required `ETag`/`Location` headers and body semantics):

18. **EHR:** `POST /ehr` → 201 (+`ETag`/`Location`, body per Prefer)/400/409; `PUT /ehr/{ehr_id}` → 201/400/409; `GET /ehr/{ehr_id}` → 200/404; `GET /ehr?subject_id&subject_namespace` → 200/404 (`404_EHR_subject.yaml`). — `operations/ehr_create*.yaml`, `ehr_get_by_id.yaml`, `ehr_get_by_subject.yaml`.
19. **EHR_STATUS:** `GET /ehr/{ehr_id}/ehr_status/{version_uid}` → 200/404; `GET /ehr/{ehr_id}/ehr_status?version_at_time` → 200/400 (invalid `version_at_time`)/404; `PUT /ehr/{ehr_id}/ehr_status` (If-Match required) → 200/204/400/404/412 (`412_EHR_STATUS.yaml` carries the latest-version headers). — `operations/ehr_status_*.yaml`.
20. **VERSIONED_EHR_STATUS:** `GET …/versioned_ehr_status` → 200/404; `…/revision_history` → 200 (`200_REVISION_HISTORY.yaml`)/404; `…/version?version_at_time` → 200/400/404; `…/version/{version_uid}` → 200/404. — `operations/versioned_ehr_status_*.yaml`.
21. **COMPOSITION:** `POST /ehr/{ehr_id}/composition` → 201 (`201_COMPOSITION.yaml`: "Content body is only returned when `Prefer` header has `return=representation`, otherwise only headers are returned", `ETag_COMPOSITION` + `Location_COMPOSITION`)/400/404/**422** (semantic validation); `GET …/composition/{uid_based_id}` → 200/**204** ("deleted at time"/deleted version, `204_because_deleted*.yaml`)/404; `PUT` (If-Match) → 200/400/404/412/422; `DELETE` (preceding version in path) → 204 (`204_COMPOSITION_deleted.yaml` with `ETag`/`Location` of the delete version)/400 (`400_already_deleted.yaml`)/404/409 (`409_COMPOSITION_with_uid_based_id.yaml`). — `operations/composition_*.yaml`.
22. **VERSIONED_COMPOSITION:** the four GETs mirror §20 with `versioned_object_uid` path id: 200/404 each, `version?version_at_time` returning `200_VERSION_of_COMPOSITION_at_time.yaml` (ETag = `version_uid`, Location = the VERSION URL). — `operations/versioned_composition_*.yaml`.
23. **DIRECTORY (FOLDER):** `POST /ehr/{ehr_id}/directory` → 201 (`201_directory.yaml`)/400 (`400_FOLDER.yaml`)/404; `PUT` (If-Match) → 200/204 (`204_directory_updated.yaml`)/400/404/412 (`412_directory.yaml`); `DELETE` (If-Match) → 204/400/404/412; `GET …/directory?version_at_time&path` → 200/204/404 (`404_directory_unknown_ehr_id_or_no_version_at_time_or_no_path.yaml`); `GET …/directory/{version_uid}?path` → 200/404. — `operations/directory_*.yaml`.
24. **CONTRIBUTION:** `POST /ehr/{ehr_id}/contribution` → 201 (`201_CONTRIBUTION.yaml`, `ETag_CONTRIBUTION` + `Location_CONTRIBUTION`)/400 (`400_CONTRIBUTION.yaml`)/404/409; `GET …/contribution/{contribution_uid}` → 200/404. — `operations/contribution_*.yaml`.

### C. Query API (`query.openapi.yaml`)

25. **Endpoints:** `GET|POST /query/aql` (ad-hoc) → 200/400/408; `GET|POST /query/{qualified_query_name}` and `…/{version}` (stored) → 200/400/404/408. `408 Request Timeout` = "Request maximum execution time is reached". — `query.openapi.yaml` paths; `operations/query_execute_*.yaml`; `responses/408_Query.yaml`.
26. **Common parameters.** All query executions SHOULD support `ehr_id`, `offset` (0-based, default 0), `fetch` ("cannot be combined with AQL-top"), and named `query_parameters` substituting AQL placeholders (supplied **without** the `$` prefix). `ehr_id` MAY alternatively be the `openEHR-EHR-id` request header; it MUST NOT be supplied for population queries. Response header: `ETag` — "A unique identifier of the resultSet". — `docs/query/Request.md` §Common Headers and Query Parameters, §About the ehr_id parameter, §Query parameters.
27. **Qualified query name.** `[{namespace}::]{query-name}` (reverse-domain namespace; name chars `[a-zA-Z0-9_.-]`); `version` is SEMVER `major.minor.patch`; on partial or absent version "the system must use the latest `version` with the supplied prefix". — `docs/query/Qualified_query_name.md`.
28. **Response.** Query results are returned as `RESULT_SET` (schema in `schemas/query/`; metadata attributes optional/implementation-dependent). — `docs/query/Response.md`.

### D. Definition API (`definition.openapi.yaml`)

29. **ADL 1.4 templates (OPT):** `POST /definition/template/adl1.4` → 201 (`201_Template_adl1_4_upload.yaml`)/400 (`400_invalid_template_content.yaml`)/409 (`409_template_already_exists.yaml`); `GET` list → 200 (`200_TemplateList_adl1_4.yaml`); `GET /{template_id}` → 200/400 (`400_invalid_template_id.yaml`)/404/406 (Accept negotiation over `application/json|application/xml|text/plain|application/openehr.wt+json`, `parameters/header/Accept_template.yaml`). — `operations/definition_template_adl1.4_*.yaml`.
30. **ADL 2 templates:** `POST /definition/template/adl2` → 201/400/409; list → 200; `GET /{template_id}` and `/{template_id}/{version}` → 200/400/404 (ADL2 text is `text/plain`, per Intro amendment SPECITS-59). — `operations/definition_template_adl2_*.yaml`.
31. **Stored queries:** `PUT /definition/query/{qualified_query_name}` → 200 (`200_StoredQuery_stored.yaml`)/400 (`400_StoredQuery.yaml`); `PUT …/{version}` → 200/400/409 (`409_StoredQuery_version.yaml`); `GET /definition/query/{qualified_query_name}` (list versions) → 200 (`200_QueryList.yaml`); `GET …/{version}` → 200 (`200_StoredQuery_get.yaml`)/404 (`404_Query_version.yaml`). A `query_type` parameter exists (`parameters/query/query_type.yaml`). — `operations/definition_query_*.yaml`.

### E. System OPTIONS

32. **`OPTIONS /` (System Options and Conformance).** Services SHOULD respond with appropriate codes/headers and potentially a payload revealing capabilities ("conformance manifest"): 200 with `Allow` header (`'GET, POST, PUT, DELETE, OPTIONS'`) and an `Options` body (`schemas/others/Options.yaml`). — `operations/options.yaml`, `responses/200_options.yaml`, `headers/Allow.yaml`, `overview.openapi.yaml`.

### F. ITS-XML / ITS-JSON payload conformance

33. **ITS-XML validity.** XML resource representations MUST validate against the published XSDs; the stable bundle is Release-1.0.2 (namespace `http://schemas.openehr.org/v1`); Release-2.0.0 is TRIAL with namespace `/v2`. — `docs/overview/Resources.md` §XML Format; `ITS-XML/README.adoc`.
34. **ITS-JSON validity.** JSON SHOULD validate against the draft-07 schemas (DEVELOPMENT state); recommended automated target is the per-release `openehr_rm_*_all.json` file; no abstract-class schemas exist (flattened definitions, `if…` polymorphism). — `docs/overview/Resources.md` §JSON Format; `ITS-JSON/README.adoc` §Design choices.

4. **If-Match hardening** (F-01-09/F-02-08): full `OBJECT_VERSION_ID` string compare, reject unparseable/absent header on operations where the OAS marks it `required: true` (412, with latest-version `ETag`/`Location`).

6. **Status-code mapping fixes**: F-02-10 (contribution mismatch → 400), F-03-09 (invalid template content → 400), F-03-13 (template GET Accept negotiation → 406/400), F-03-14 (`query_type` honoured, 400 on unknown), F-01-11 (align EHR/EHR_STATUS format offering with the OAS or PORT-NOTE the deliberate extension).
