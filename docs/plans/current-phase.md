- **The goal (ADR-006).** Build the **best-possible EHRbase in Rust**: openEHR-spec-conformant, behavior-compatible with EHRbase at the REST/AQL surface, as a **modern idiomatic application** that consumes the generated `openehr-*` crates directly as its domain model. Use proper crates — `axum`+`tower-http`, `sqlx`+`sea-query` (NOT sea-orm), `oauth2`/`openidconnect`/`jsonwebtoken`/`argon2` for **Basic + OAuth2/OIDC auth** (Stage 1; RBAC is Stage 2), `utoipa`, `moka`, `jiff`, `testcontainers` PG18. Do **not** hand-roll what a good crate provides, and do **not** mirror EHRbase's Java class structure. The bespoke server logic no crate provides — the AQL engine (AST→ASL→SQL), versioning, validation, RM↔JSONB mapping — is written idiomatically **following EHRbase's proven algorithm as the reference** (`crates/ehrbase/src/{aql,service,rm_db_format}/` Java is the read-only reference). The **parity harness** (P19) is the acceptance instrument.
